# Bunny UI / Image QA 标准

## 1. 本次修复的根因

旧版首页把 1366×1024 当成绝对固定画布，并在浏览器 viewport 变窄时继续使用固定列宽；结果是 Pad 上出现内容被裁切、右侧卡片只显示一部分、主体 Bunny 被底部区域遮挡等问题。

旧版还把部分功能入口依赖 emoji / AI 生成整张 UI 图，导致“图和语义不对应”和“图片里中文乱码”。

## 2. 新规则

### 布局

- 设计基准：Pad 横屏 1366×1024。
- 运行时：`width: min(100vw, 1366px)`、`height: min(100dvh, 1024px)`。
- 禁止页面产生横向滚动作为正常交互。
- 所有主要区域使用 `minmax(0, 1fr)` / `minmax(...)`，禁止核心容器使用不可收缩的固定宽列。
- BottomNav 必须为安全区域预留空间。
- 900px 以下进入窄屏降级布局。

### 图片

- **图片只负责视觉，不负责中文文字。**
- AI 生图禁止包含标题、按钮、中文说明、汉字教学文字、数字 UI。
- 页面中的中文全部由 React/HTML/CSS 渲染，确保字体、清晰度和可读性。
- 角色、场景、物体必须按“单一语义目标”生成：需要兔子，就只验收兔子；需要山，就验收清晰山体；需要水，就验收明确水流。
- 角色必须通过轮廓特征验收：Bunny 必须有明显长耳、白色毛发、粉色内耳、圆眼和红色书包。
- 内容图片必须有对应的 asset id 和用途，不允许一张图复用成语义不同的对象。

## 3. 资产分层

```text
assets/
  character/       # Bunny / companions / NPC
  background/      # forest / meadow / pond / sky
  object/          # tree / mountain / water / book / star ...
  story/           # 绘本逐页插画
  ui/              # 非文字 UI 装饰
```

文本、拼音、字形、按钮等始终由应用层渲染。

## 4. 图片验收清单

- [ ] 一眼能识别目标对象
- [ ] 主体没有被裁切
- [ ] 主体位置与页面语义一致
- [ ] 不包含 AI 生成的乱码文字
- [ ] 不包含错误的汉字
- [ ] 不包含随机数字或假 UI
- [ ] 色彩符合 Bunny 视觉规范
- [ ] 角色比例在不同页面一致
- [ ] 同一个角色在不同页面外观一致
- [ ] 图片尺寸满足目标页面，不靠 CSS 强行拉伸变形

## 5. Pad 首页布局标准

```text
┌──────────────────────────────────────────────┐
│ TopBar     Bunny 世界          学习进度      │
├──────────────────┬───────────────────────────┤
│                  │  故事王国   │ 汉字花园    │
│      Bunny       ├─────────────┼─────────────┤
│   角色/问候区    │  冒险乐园   │ 我的  小屋  │
│                  │             │             │
├──────────────────┴───────────────────────────┤
│ 首页 │ 故事 │ 汉字 │ 今日 │ 游戏 │ 小屋      │
└──────────────────────────────────────────────┘
```

原则是“一个主角 + 四个清晰入口 + 一个统一导航”，避免首屏同时堆太多指标。

## 6. 回归检查

每次修改通用布局后至少检查：

1. iPad Pro 横屏 1366×1024
2. 1280×960
3. 1024×768
4. 浏览器缩放 100% / 80% / 50%
5. 首页、绘本、汉字、游戏、每日计划、成长、家长报告
6. 右侧内容不能被裁切
7. BottomNav 不能遮住内容
8. 文字不能溢出卡片
9. 图片不能变形
10. 触控目标不小于 56px
